## What this means for the design

- `email` is not unique (2,632 distinct across 10,000 users), so `users.email` has no unique constraint and notifications are keyed on `user_id`.
- Cohorts keyed on the full profile would save almost nothing (9,869 signatures for 10,000 users). Cohorts keyed on one criterion's `depends_on` collapse to a handful: an employment-only criterion has 3 signatures per product.
- The file has no dirty rows, so `gen_users.py --dirty-rate` injects bad rows to exercise the ingest reject path.
- Line endings are CRLF: the ingest reader must not assume LF.
- The numeric fields are independent (|r| < 0.05), so the generator can sample each field from its own marginal distribution and still match the sample.
- `monthly_income` comes in steps of 1,000, so a cohort band finer than that can't separate any users.
- `credit_score` comes in steps of 5, so a cohort band finer than that can't separate any users.
